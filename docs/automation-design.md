# Phase 11: Automation & Autonomy Design (Pass 1, 2 & 3 Audit) — Re:NeWrld

Governed by **Project Growth v1.1.0** and [`docs/governance.md`](governance.md).

---

## 1. Introduction & Authority
This document defines the authoritative **Automation & Autonomy Architecture** for **Re:NeWrld**. It establishes clear operational boundaries for deterministic automated workflows, event triggers, synchronous and asynchronous execution, retries, idempotency, failure handling, atomic rollback, containment, auditability, and the strict demarcation between **Deterministic System Automation** and **Optional AI Autonomy**.

---

## 2. System Automation vs. AI Autonomy
- **Deterministic System Automation**: Governs predictable, programmatic platform workflows such as automated publishing validation graph traversal, database backup snapshots, session state persistence, and transaction rollbacks. Executes entirely without AI intervention.
- **Optional AI Autonomy**: Refers to bounded generative assistants or simulation wrappers (such as AI-assisted prose styling or future NPC reasoning). AI autonomy is strictly optional, non-authoritative, sandboxed, and prohibited from executing unapproved domain mutations or canon changes.

---

## 3. Core Automated Workflows (MVP)

### 3.1 Publishing Validation Workflow (Synchronous / Automated)
- **Trigger**: Creator initiates world publishing (`POST /api/v1/worlds/{world_id}/publish`).
- **Execution**: Automated graph traversal checks target reference existence, detects orphaned scenes, verifies terminal ending reachability, and validates condition/mutation references.
- **Authorization**: Creator world ownership check via RBAC middleware.
- **Failure Handling / Rollback**: If structural validation fails, publication is rejected with structured errors; draft status remains unchanged.

### 3.2 Reader State Persistence & Rollback Workflow (Atomic ACID)
- **Trigger**: Reader selects a choice (`POST /api/v1/sessions/{session_id}/choices`).
- **Execution**: Synchronous condition evaluation, state mutation processing, and timeline history logging inside a PostgreSQL ACID transaction.
- **Idempotency**: Client-supplied idempotency key prevents duplicate mutations during network retries.
- **Failure Handling / Rollback**: If database persistence fails, the transaction rolls back completely, preventing partial state corruption and returning a standardized error envelope.

---

## 4. Resilience, Error Handling & Containment
- **Retries & Backoff**: Transient database or network storage errors trigger exponential backoff with jitter up to defined retry limits.
- **Idempotency Keys**: Critical state-mutating requests require idempotency tokens to guarantee safe, at-most-once state evaluation effects on retry.
- **Circuit Breakers & Fallbacks**: Optional external AI gateway calls (`IntfAIGateway`) are guarded by circuit breakers; upon timeout or error, the system seamlessly falls back to pure creator-authored prose.
- **Audit Logging**: All automated workflows generate Pino structured JSON audit logs tagged with request correlation IDs.

## 5. Future Automation & Autonomy Boundaries (Pass 2 of 3 — Tiers 1–3 Simulation & Workers)

### 5.1 Future Asynchronous Background Execution (`IntfJobQueue`)
- **Background Worker Trigger**: Scheduled or asynchronous execution for Post-MVP workloads (automated path simulation bots, batch publishing validations, asynchronous AI media generation, and cross-timeline outcome pooling).
- **Architecture**: Backed by an abstracted queue interface (`IntfJobQueue`) preparing for Redis + BullMQ in Post-MVP. Zero idle infrastructure cost for MVP.

### 5.2 Future Event Triggers, Ordering & Scope Limits
- **Event Ordering**: Sequential causal ordering is enforced for reader timeline events, ensuring state mutations apply strictly in chronological order.
- **Scope Limits**: Simulation and background workers are strictly scoped to specific world IDs or active session IDs, preventing cross-tenant data pollution.

### 5.3 Creator Approval Gates & Global Kill/Disable Controls
- **Creator Approval Gates**: Autonomous simulation changes (e.g., suggested world lore expansions or canon adjustments generated by future AI assistants) require explicit **creator approval** before committing to Canon.
- **Kill/Disable Controls**: Platform operators and creators maintain master kill/disable switches to instantly halt autonomous simulation loops, AI background tasks, or cross-timeline synchronization without affecting core deterministic reading sessions.

### 5.4 Separation & Security Guarantees
- **No Authority Bypass**: Automation and autonomy engines are strictly prohibited from bypassing Canon Data, Reader State isolation, publishing validation, or RBAC security boundaries.
- **Optionality**: All future simulation and automation tiers remain strictly optional extensions.

## 6. Autonomy Security, Provenance, Audit Trails, Failure Containment & Human Override (Pass 3 of 3)

### 6.1 Provenance, Attribution & Audit Trails
- **Attribution**: Every automated background action, simulation event, or AI-assisted suggestion generates cryptographically correlated audit records linking the originating task ID, world ID, and user/session scope.
- **Immutable Provenance**: Autonomous systems can never obfuscate their actions; all state changes or simulation outcomes are explicitly tagged as system-generated or AI-assisted.

### 6.2 Failure Containment, Recovery & Human Override
- **Containment Sandboxes**: Asynchronous simulation workers and AI reasoning loops operate inside isolated execution sandboxes. If an anomaly or unauthorized mutation attempt occurs, the sandbox terminates immediately without affecting core reader runtime sessions.
- **Human Override**: Creators and platform operators retain supreme override authority to inspect, rollback, disable, or purge any automated simulation artifact or suggested update.
- **Simulation Outcomes vs. Canon**: Simulation outcomes and autonomous decisions strictly record as runtime **Experience / Timeline events** for the reader session and *never* alter Published Canon unless explicitly promoted via a creator-authorized, versioned publishing update.
